# 灯塔世界｜3D 模型资产制作与修改规范

> 项目长期执行规范。依据 2026-11-02 的四棵椰树建模、纠错、减面和 GLB 材质修复过程。适用于以后所有已确认的低多边形模型资产。

## 最高原则：原模型是唯一造型依据

- **修改已有模型，必须从已确认的原始 GLB/Blend/几何网格出发。** 不得仅根据截图或文字新建「类似的」替代模型。
- 已通过的树干弯曲趋势、树冠轮廓、叶片数量和朝向、比例、配色、世界尺度和局部原点都属于锁定条件。仅修改用户明确要求的维度。
- 「减面」的定义是原几何上的简化/重拓扑（可以采样原顶点与截面），不是另造一棵低面数树。
- 改一个问题，不顺带重做外观；除非用户显式同意，否则不得擅自修改材质、造型或空间关系。

## 最重要的教训

1. **不要误把独立重新建模当作减面。** 最初制作的 82-tris 低模树不是原模型的简化版，造型不一致，应弃用；正确做法是以已批准 T01 为源进行重拓扑，取得 102 tris 且保留 9 片叶。
2. **不要只看导出前的 RGB 就断言“颜色没变”。** GLB/glTF 的颜色空间、顶点颜色 COLOR_0、PBR baseColorFactor、材质和渲染器的 tone mapping 都可能改变显示效果；必须检查最终 GLB 在目标 3D 查看器中的颜色。
3. **不能只保留 COLOR_0 就假设所有查看器都会正确上色。** 如需稳健兼容，应在 GLB 内明确写入有效的 glTF PBR 材质和颜色，必要时按面拆分 primitive；禁止依赖外部贴图或预览脚本临时着色。
4. **“接触”不等于靠近。** 检查叶片根部与树干顶部在 X/Y/Z 三维空间里的相对位置，要求几何真实接触或小幅重叠，不可产生肉眼可见的悬空缝隙。
5. **先单件测试，再批量改动。** 用户明确选择过方案 B：先检查 T01 的简化效果，获准后再按相同规范做 T02–T04；不要未经确认一次性重制整套。
6. **不得混淆本地生成、仓库提交和网页上线。** 只有确实提交并校验 GitHub 中的文件、编辑器素材注册和线上加载，才能说“已替换地图编辑器”；只修改 /mnt/data 下的文件，应明确说“仅本地文件已替换”。不允许假报验证结果。

## 几何与配色校验

- 优先以 **Triangles（三角面）** 作为预算口径，而不是四边面或单纯顶点数。
- 本批四棵椰树目标约 100 tris/棵，用户已接受：
  - T01 海风高椰：681 → **102 tris**；原有 **9** 片叶。
  - T02 矮冠椰树：706 → **108 tris**；原有 **10** 片叶。
  - T03 迎风斜椰：624 → **96 tris**；原有 **8** 片叶。
  - T04 幼年小椰：576 → **96 tris**；原有 **8** 片叶。
- 与原版对比时，检查主轮廓、树干曲度、叶片方向、树冠大小、底部原点、上下边界，必要时对比相同机位截图。
- 每次导出后，重新**读取生成的 GLB**，实际统计 triangles、mesh、primitive、材质和顶点 bounds；不要只依据建模脚本的理论结果。
- 材质标准：延续已确认的**深红棕树干、偏饱和绿色树叶、低多边形明暗色块**；尽量不用高光、金属感或油画贴图。GLB 应自带材质数据，便于不同 Three.js/gltf 查看器显示。
- 美术一致性优先于纯粹追求最低面数；没有得到更严格要求时，「约 100 tris」可视为 96–108 的已批准区间，但若明示“≤100”必须严格满足。

## 工作顺序（以后默认执行）

1. 找到**当前正式批准的原模型文件**，并另存不可覆盖的高面数备份。
2. 明确用户要动的唯一目标（例如：接合 / 减面 / 上色 / 导入），其余全部锁定。
3. 对原模型做几何分析：分离树干/叶片组件，统计面数和颜色，确认坐标系与局部原点。
4. 直接基于源网格修改；若有风险，先导出 **1 个测试样件**。
5. 自检：triangle 数、三维接合、实际材质、配色、形体和 GLB 可读取性。
6. 得到用户认可后批处理变体，保留原文件标识和稳定资源 ID。
7. 如任务涉及地图编辑器，更新 GitHub 编辑器实际引用的 **四个 GLB**（而非只改本地压缩包），校验素材注册、预览、放置/选择、X/Y/Z 移动、旋转、缩放、保存及导出 JSON。
8. 汇报时严格区分：本地完成 / 仓库已提交 / 线上验证通过；提供具体链接和面数统计。

## 地图编辑器资产兼容约束

- 仓库：`raynacocobobobo-arch/DND`，编辑器位于 `gh-pages` 分支的 `lighthouse-editor/`。
- 椰树素材为四个**独立元件**；既有素材 ID 为 `coastal_tree_t01` 至 `coastal_tree_t04`，并使用固定的 GLB 路径 `lighthouse-editor/assets/palms/t01_seabreeze_tall.glb` 等。
- 维持 Y-up、树干底端局部原点、独立缩放与旋转；不能修改或重建整张岛屿地图。
- 已在 GitHub 注册过四棵椰树，但**低面数版本最初仅在本地生成**。后续需单独核对 GitHub 上模型是否已替换；此文档本身不代表 GLB 已部署。

## 错误防范清单

- [ ] 是否确实基于已经确认的模型，而不是凭空重做？
- [ ] 有没有修改用户没有授权改变的配色、比例、方向或树形？
- [ ] 树干与叶片在导出 GLB 中真的接触吗？
- [ ] 实际 triangles 是否达标，且读取 GLB 回验一致？
- [ ] 标准 glTF 查看器能读出实打实的彩色 PBR 材质吗？
- [ ] 是否提供原高面数模型备份和独立测试版？
- [ ] 如果说编辑器已替换，GitHub 里的 GLB 文件、引用和线上功能是否都已核对？

**口径：外观锁定；只改指定项；先验收再扩展；数据和线上状态必须可核验。**

## Cliffy Coast 导入与编辑器比例规范（2026-11-02）

- **Cliffy Coast 外部资源的默认放置缩放为 30%（scale=0.3）**。这是用户确认的原尺寸的 30%，不是缩小 30% 至 70%。
- 保持导入 GLB 的原始几何尺寸和轮廓，优先在地图对象记录的 `scale` 字段设定 0.3；不为缩放擅自重建或重新设计模型。
- 编辑器允许直接键入旋转角度（单位 °）与缩放百分比（单位 %），同时保留原滑杆和 X/Y/Z 三轴手柄。
- 新资产试用必须先 **单模型** 检查原形、材质、面数、比例、加载、旋转、移动与保存；双模型拼接检查通过后才可批量转换。
- 首批实验：`Cliffy Coast/Tree1.fbx` 和 `Tree3.fbx`，原始网格分别为 1203 和 639 tris，GLB 位于 `lighthouse-editor/assets/cliffy-coast/tree1.glb`、`tree3.glb`。地图素材注册 ID 为 `cliffy_coast_tree1` 与 `cliffy_coast_tree3`，两棵树是独立元件。
- 如第三方资源授权未明确允许，将其原始/转换模型提交到公开仓库前需确认许可条件；不假设购买即包含原始模型再分发权。
