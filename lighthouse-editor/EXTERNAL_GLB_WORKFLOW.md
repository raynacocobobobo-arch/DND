# 灯塔地图编辑器：外部 GLB 资产流程（V4.2.0）

更新时间：2026-11-02。当前项目：`lighthouse-editor/`；与现有原版岛屿并行工作，不修改已批准的椰树与灯塔模型。

## 首次验收（建议按顺序）

1. 打开 `lighthouse-editor/`；确认页面显示 **V4.2.0**。
2. 使用顶部 **导入地图** 加载 `Cliffy_Coast_Editor_Test_Project.json`，其中包含两个测试 GLB 的二进制数据。文件中示例有两块组合悬崖和一块礁石。
3. 确认场景出现 **示例悬崖 A**、**示例悬崖 B** 与 **示例礁石**；选中 A 应同时选中 B，且右侧对象管理器显示 **[组合]**。
4. 检查 GLB 贴图、颜色、位置、X/Y/Z 三轴平移；组合可整体移动、拆分。不要直接用鼠标拖动组合，需使用三轴移动手柄。
5. 选择单一外部 GLB，点击 **模型外框贴边**，仅在附近存在另一个 GLB 且两者投影重合时可对齐。
6. 刷新页面，确认从同一浏览器 IndexedDB 恢复模型，原地图对象保持。
7. 点击 **导出完整工程（含 GLB）**，重新导入该 JSON，确认不缺失二进制资产。
8. 若导入一般 GLB：点击左侧 **选择 GLB 文件（支持多选）**，成功后素材库新增 **外部地形 GLB** 或 **外部模型 GLB**，选择缩略图后点击画布放置。

## 数据和兼容约束

- 直接支持的导入格式为 **GLB（二进制 glTF）**。Unity `.unitypackage` 和 FBX 必须先解包并转 GLB。
- 单文件 25MB，单浏览器最多 220 个外部模型，超过 50 万 triangles 的单模型被拒绝以保护网页性能。
- 浏览器模型内容存储在 **IndexedDB**。普通 **导出 JSON** 只导出场景对象及 GLB 内容哈希 ID，不包含二进制模型。跨设备或浏览器分享必须使用 **导出完整工程（含 GLB）**。
- `lighthouse/shared-map.js` 的 `normalizeMap()` 已增加 `ext_glb_<24 hex>` 素材 ID 及 `grp_...` 组合 ID 的保留机制。
- 实际模型数据 **不提交到公开 GitHub 仓库**，避免未经核实的第三方资源再次公开分发。
- 编辑器的外部 GLB 显示与保存已加入；**游戏预览和正式游戏尚未接入外部 GLB 渲染链路**，可能忽略这些 GLB 对象。原版资产和已有地图逻辑保持不变。
- **“模型外框贴边”** 是世界坐标下的 AABB 包围盒对齐，不检查顶点拓扑。不能保证复杂低多边形悬崖表面连续。
- **“组合选中模型”** 是编辑器内可逆的对象分组，组合后可整体平移；**并非网格合并、焊接顶点、删除重叠内部面**。
- 真正的“相邻地形几何合并”应在检查 Cliff Plateau 的边缘拓扑与坐标单位后单独实施。不能用普通对象分组冒充几何焊接。

## 后续合并的推荐验收门槛

1. 地形单位、旋转、缩放和 X/Z 模块边界可量化，边缘落点一致。
2. 相邻两侧的边界顶点映射可检验，存在不同顶点划分时先重采样边界，不强制焊接异构外框。
3. 避免内部重合面、法线翻转、UV 跨缝错位；保留原低面数风格与材质。
4. 合并后可独立导出为 GLB，具有真实 tris、bounds 和材质回验数据。
5. 记录原始模块和变换，使编辑器内拆分可逆；新资产导出后仍可在目标渲染器读取。

## 资产处理优先级

先以 `Cliff_Plateau1.glb` 和 `RockGrey1.glb` 做初测，再检查其余 15 个地形 FBX 的边缘，避免先批量导入后返工。
