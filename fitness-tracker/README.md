## V2.0 iPhone 16 专用交互

- 按 iPhone 16 标准款 **393×852 CSS px** 竖屏设计，PWA 添加到主屏幕后首页目标为单屏：顶部今日/本周卡路里 + 11 个运动快捷卡片 + 固定底部五项导航。
- 首页不再渲染额外页面标题、长提示「快速打卡」或「当前入口没有读取到历史记录」；空记录/异常相关警示只在设置→数据备份中以简洁文字呈现。
- 双列六行，最后一张横跨双列；以动态高度均匀分配余下空间。卡片包含运动名称、减号、数字下拉、加号、打卡，保持 4 组默认值及已保存的每组参数。

- 第二页名称统一为 **「手动步数」**，总步数、各段起/止累计步数、修改、删除全为手动操作，不向健康 App 或快捷指令请求读数；沿用多段排除净步数公式。
- 黄黑主题、拳头桌面图标不变；旧训练记录 `hermes_fitness_journal_v1`、休息日 `hermes_fitness_rest_days_v1` 和上版恢复快照均不重置。设置中保留导入/导出和恢复。
- V1.9 代码保存在 `release/fitness-tracker-v1.9`，供回退与追查数据。

## V1.9 本地数据保护与纯手动步数去重

- **不再启动健康快捷指令**：移除第二页读取 Apple 健康的按钮与回跳处理，保留用户原有服务和夜间自动上报不作修改。
- 第二页默认直接呈现 **今日累计步数输入/保存** + **多段扣除区间输入**；无需展开次级面板。每段填写类型（健身房/骑车/乘车/其他）、开始累计步数、结束累计步数（可先留空），支持修改/删除，逐段扣除。
- 净步数 = 今日累计总步数 - 已完成的所有区间累计差值，重叠区间不可保存。同日反复更新步数，只更新同一条 `stepMode:daily-net-v1` 自动管理的步行记录。
- 当天已记录的总步数若早于新手动区间的读数，保存该区间时会将总步数提升至当前区间内最高的累计读数；之后可继续输入当天最终总步数。
- 保护 `hermes_fitness_journal_v1` 本地训练存储：**取消首次打开时自动保存空初始状态**；遇到原始 JSON 损坏或无法读取时，显示警告并拒绝普通写入覆盖。
- 每次成功保存变更前，尝试将以前的有效记录保存到 `hermes_fitness_journal_recovery_v1`，优先保留记录条数最多的版本（本机快照，不上传服务器）；在设置页检测到快照时提供「恢复本机快照」，恢复前必须确认。
- 如果原始 JSON 无法解析，设置页提供「导出原始内容」，导入备份前保留损坏原文，避免无声覆盖；原先「清空所有训练记录」按钮已撤下。
- 如果当前入口没有读到历史记录，首页和设置页显示提示，帮助排查 Safari 与主屏幕独立应用的本地存储；**不能保证恢复已被系统清除的本地数据**。
- 记录的组数、卡路里、热量系数、其他训练记录与独立的 `hermes_fitness_rest_days_v1` 休息日数据不做强制迁移。

## V1.5 独立「步数去重」页面与多段排除

- 移动端底部导航五项：**打卡 / 步数去重 / 日历 / 历史 / 设置**。「步数去重」固定为第二个入口；不再放在首页隐藏的折叠区里。原日历改为第三项。
- 同一天可以添加多段扣除区间，类型可选：健身房、骑车、乘车、其他。每段分别保存 **开始累计步数** 和 **结束累计步数**；可只保存开始值，后续通过「修改」补充结束。
- 例如全天 12,000，第一段 5,000→6,000，第二段 8,000→9,000，则净步数 = 12,000 − 1,000 − 1,000 = **10,000**。
- 区间可以修改、删除、按起始累计读数排序；重叠区间禁止保存，避免重复扣除。未结束的区间不会提前扣除。结束读数不能大于已经保存的全天总步数，须先更新总步数。
- 专用第二页有「当天累计总步数」输入；首页走路卡片仍可记录全天总步数。两者修改同一条管理中的净步行记录，不会重复累加。
- 继续复用本地键 `hermes_fitness_journal_v1`，日计步数据存于 `stepDiary[日期].sessions`；将旧版单区间 `gymIn/gymOut` 自动转换为内存中的一条健身房区间，不在打开网页时改写历史数据。
- 仍复用 `stepMode: daily-net-v1` 的现有记录标识；修正步数时只更新同一天自动管理的步行记录。原始其他运动、过去记录、体重、目标、日历休息日不重写。
- JSON 备份可完整保存多段区间；旧版单区间 JSON 可导入并自动兼容。
- 适用同一设备/同一计步源连续累积的读数。此方法不能识别骑车/乘车时哪些是真实走路，属于手动估算，可能也会扣掉区间内真实步行。
- V1.4 定版保存在 `release/fitness-tracker-v1.4`。

## V1.4 日步数去重与打卡区块调整

- 首页不再显示「本周打卡」七日卡片；该区块只显示在「日历」页。首页今日 kcal、本周 kcal 进度保持不变。
- 首页 11 个项目与手机四列布局不变；走路卡片现在输入 **当天累计总步数**（不是本次单独走了多少步）。
- 新增收起式「步数去重 · 入馆／离馆」：到健身房前填写同一设备上看到的累计步数，离馆后填结束累计步数。允许分两次保存。
- 计算公式：**非健身房步数 = 当天累计总步数 − (离馆累计步数 − 入馆累计步数)**，结果不小于 0；步行 kcal 仅根据非健身房净步数计算。入馆或离馆缺失时暂不扣除。
- 椭圆机、自行车、力量等独立记录的 kcal 仍单独计算，不会再次把已扣除的健身房计步折算为步行 kcal。
- 当天走路卡片再次打卡，会更新同一条自动管理的步行记录（`stepMode: daily-net-v1`），不重复新增。修正入馆／离馆步数后也会在累计总步数足够时更新该记录。
- 如果当天已经存在旧的手动步行记录，首次使用新模式前提示可能重复计入；**绝不自动删除旧记录**。
- 新的计步快照位于原 `hermes_fitness_journal_v1` 状态里的 `stepDiary` 字段，并随 JSON 备份导出／导入；原有运动记录与 `hermes_fitness_rest_days_v1` 不迁移不改写。
- 适用单个健身房入离馆区间；使用同一个计步源，否则两次累计步数不能直接相减。此法是避免重复计步的近似估算，可能同时排除健身房内的真实走路步数。
- V1.3.1 基线独立保留于 `release/fitness-tracker-v1.3.1`。

- 新导航「日历」，按月显示训练/休息/未打卡状态，点击日期查看当天训练项目和卡路里

- 现有训练记录自动算作当天运动打卡，**不重复新增运动记录**
- 当天没有运动时可按「今日休息打卡」登记休息日（0 kcal），支持撤销
- 休息日存储在独立的 `hermes_fitness_rest_days_v1` localStorage 键中，不触碰现有 `hermes_fitness_journal_v1` 
- JSON 备份会同时导出 restDays；导入旧备份（没有 restDays 字段）不会清空当前休息打卡
- 连续打卡天数计算从今天回溯，如果今天未打卡则从昨天开始计算，避免当天尚未结束便清零
- 未来日期不能提前标记打卡；卡路里累计始终只来自真实运动记录

## V1.0 范围

- 首页九个固定项目：椭圆机、拉背、划船、飞鸟及引体、走路、自行车、蛙泳、靠墙静蹲、仰卧起坐
- 默认值：有氧/蛙泳/自行车 20 分钟；力量/静蹲/仰卧起坐 3 组；走路 5000 步
- 力量动作每组固定 15 次；靠墙静蹲每组固定 45 秒
- 顶部展示今日消耗、本周消耗、距离周目标剩余数及进度条
- 打卡 / 历史 / 设置三级导航，历史可编辑
- 本地 JSON/CSV 导出，JSON 导入
- 离线 PWA 支持

## 保存机制与兼容性承诺

- **用户训练记录存储在浏览器 localStorage，固定键 `hermes_fitness_journal_v1`。**
- 升级至 V1.0 不改变存储键、不修改历史数据的名称/组数/次数/卡路里、不清空已有数据。
- 已有“飞鸟”历史记录仍显示为“飞鸟”，之后新记录的快捷入口名称为“飞鸟及引体”。
- 不预装用户私有训练历史；GitHub Pages 只发布前端代码。
- 修改站点时不要改动存储来源域名和路径；不要对记录结构作无迁移变更。
- 用户应定期导出 JSON，清理 Safari 网站数据可能造成永久丢失。

## 计算

- 椭圆机：5 MET × 3.5 × 体重(kg) / 200 × 分钟
- 自行车、蛙泳：6 MET × 3.5 × 体重(kg) / 200 × 分钟
- 常规力量：组数 × 15 × 0.22 kcal
- 仰卧起坐：组数 × 15 × 0.15 × 体重(kg) / 68
- 靠墙静蹲：3 MET × 3.5 × 体重(kg) / 200 × (组数 × 45 / 60)
- 走路：步数 × 0.04 × 体重(kg) / 70
- 结果四舍五入，属于简化估算而非精确测量

## 冻结说明

V1.0 基线固定保存在 `release/fitness-tracker-v1.0` 分支，V1.1 的日历代码另外开发和发布。后续版本不应覆盖历史训练数据或更改原始存储键。
