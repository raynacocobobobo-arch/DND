# HermesTodo｜视觉艺术指导与网页执行规范 V4

> 状态：视觉方向与制作验收标准；**不是已经通过美术审定的终版网页**。  
> 参考：用户提供的中世纪执旗女骑士插画（竖版 735 × 1103）。  
> 项目：`HermesTodo`（React/Vite/TypeScript）；不改变任务、情境、AI 业务逻辑。  
> 主题：**THE STANDARD / 旗手与秩序**。  
> 判断标准：**让网站像一幅能用的史诗画，而不是给普通待办列表换一层中世纪皮肤。**

## 01. 艺术概念：由叙事到视觉，而非由纹样到界面

原图有清晰的三重叙事：一位执旗者站在人群之前；金色日轮给予人物精神上的主轴；红白旗帜与哥特城邦连接人物、历史与远方。油彩/纸张肌理提供时光感，但锐利的五官、盔甲、旗帜剪影保证了图像的可辨识度。

网页对应关系不是“任务 = 剑、逾期 = 血、完成 = 奖章”这样的字面拟物。映射应更克制：

- **旗手** = 主动掌握生活/工作的人；是品牌的唯一人物主视觉。
- **旗帜** = 贯穿不同页面的方向感与行动流线；不用于遮挡文字。
- **日轮** = 视觉焦点及精神性的空间组织工具；不作为随处可见的装饰圆。
- **哥特建筑与远景** = 长期目标、时间与秩序，作为低对比背景。
- **羊皮纸** = 信息载体；任务可读性高于古旧感，不模仿厚重羊皮卷。
- **鸢尾花** = 品牌标记，只在 LOGO、章节起点和极少数分隔位置出现。

### 原图视觉优先级

1. 人物脸部、视线、握旗的手与盔甲轮廓：第一视觉中心；**绝不被 UI 面板压住**。
2. 金轮＋大形红白旗：决定明暗与构图方向。
3. 建筑剪影和军阵：建立深度、尺度、历史感。
4. 装饰纹样：补充，而不是抢主角。
5. UI：在预先留出的区域放置信息，不允许后期“哪里有空塞哪里”。

### 必须避免

- 不使用粗线条 SVG 来替代画面里的建筑、人物、旗帜和日轮。
- 不把“整张带文字 UI 的 AI 概念图”作为网页背景。
- 不全站重复贴大头像、透明骑士、金色日轮或旗帜。
- 不通过高强度模糊、纹理噪声、金色发光来制造所谓“艺术感”。
- 不把**简单 AI 放大**当成真实的高分辨率绘画源文件。
- 不增加现有 React 项目并不存在的“日历”“天气”“统计”功能入口；视觉稿必须忠于已实现业务。

## 02. 桌面端构图：独立画面与真实界面相互构成

基准画幅：1440 × 900 CSS px，DPR 1 与 2 都要单独验收。不是像素级固定定位；下列数值是起稿基线。

```text
┌────────────┬──────────────────────────┬─────────────────────────────────────┐
│  152 导航   │        330 人物画区        │          余宽：工作主区               │
│            │          女骑士           │    头部：一句核心语 / 日期 / 状态      │
│  品牌徽记   │      金色日轮在上方        │    44–52px：快速输入                 │
│            │  旗帜从左上越过画区边缘     │ ┌────────────────────┬─────────────┐ │
│  首页       │                          │ │ 任务清单：首要任务  │   今日进度   │ │
│  情境       │      画面保留完整人物      │ │ 已完成/待办/逾期    │   情境概览   │ │
│  AI        │  脸、手、铠甲始终可辨认     │ │ 支持真实点击/编辑    │   AI入口     │ │
│            │                          │ └────────────────────┴─────────────┘ │
│  安静的页脚 │     建筑占中后景          │   任务文字、行高、状态对比优先          │
└────────────┴──────────────────────────┴─────────────────────────────────────┘
```

- 画面与工作区不是叠满屏的“双重 UI”。主视觉主要占左侧纵深，工作区内只在顶部局部延续红白色流线。
- 以**人物脸部中心坐标**作为媒体安全区锚点，而不是简单 `background-position: center`。
- 任务卡片保持 680–900px 左右的可读宽度，右侧栏最小 238px；空间不足时右侧栏下移，不挤压任务名称。
- 旗帜可有“越界”感，但跨入交互区必须由透明渐变渐弱；禁止影响焦点框、文字或点击。
- 顶部不重复一行很大的「首页」；文学性标题与功能标题各自承担不同层级。
- 不要像过往版本一样在人物区叠一张半透明的大日期面板。

## 03. 手机端：另做构图，而不是硬裁桌面壁画

基准：390 × 844 CSS px；另验 320、375、430 宽度及 iOS 安全区。

```text
┌───────────────────────┐
│  主视觉 250–300 高     │
│  人物脸处于上部安全区   │
│  日轮与旗帜保留方向感   │
│  留白位置放短标题/日期  │
├───────────────────────┤
│  快速添加任务 44–48 高  │
│  今日待办标题/筛选      │
│  ┌─────────────────┐   │
│  │ 真实任务行 1      │   │
│  │ 真实任务行 2      │   │
│  │ 真实任务行 ...    │   │
│  └─────────────────┘   │
│  进度/情境/AI 向下排列  │
├───────────────────────┤
│ 首页   情境   AI 导航    │
└───────────────────────┘
```

- **首屏可执行性**：在 390 × 844 测试画幅，至少显示快捷输入与任务列表首条，不能让人物主视觉吞掉整屏。
- 不使用手机端“原图缩小后塞进 300px 横幅”的做法。需要**手机专用构图成品**，但人物身份、铠甲及旗帜元素与桌面版一致。
- 尽量不裁掉头部、旗杆握持动作和旗帜方向；人物脸与按钮之间预留 ≥24px 视觉缓冲。
- 关键操作按钮触控尺寸 ≥44×44px；底部导航不遮挡内容；动态键盘弹出后表单可用。
- 320px 设备上人物构图可进一步收紧，但不得使用模糊来掩饰画质。

## 04. 视觉配色（设计令牌）

| 语义 | HEX | 使用 |
|---|---|---|
| Midnight Ink | `#101B25` | 画布、导航、深色容器 |
| Gothic Slate | `#263B47` | 结构背景/选中层级 |
| Banner Crimson | `#962F2D` | 任务主要操作、旗帜与极少量强调 |
| Old Gold | `#C9A36A` | 标志/细分隔/重点结构线 |
| Halo Gold | `#E8C789` | 小面积高光，不作正文底色 |
| Warm Parchment | `#F3E8D6` | 内容卡片主表面 |
| Paper Highlight | `#FCF5E9` | 输入框 / hover 状态 |
| Body Ink | `#302B27` | 浅底正文 |
| Muted Ink | `#776D60` | 浅底次要标签 |
| Overdue | `#A6403B` | 逾期信息专用，结合文字区分状态 |

使用比例起稿：**深蓝黑 35% / 绘画 25% / 纸面 30% / 酒红与旧金合计 ≤10%**。不要让每个组件都变成红金配色。

### 字体

- 中文史诗/章节标题：`Noto Serif CJK SC`, `Songti SC`, serif；只用于标题、关键引言。
- 常用操作和任务正文：`PingFang SC`, `Noto Sans CJK SC`, system-ui。
- 英文品牌与辅助标签：`Cormorant Garamond`（待字体授权与加载评估）/ Georgia。
- 内容字号：任务标题 14–16px / 1.5 行高；次要说明 ≥12px；极小英文字母可以 10–11px，但不是业务信息。
- 每页至多一种艺术性大标题。严禁把任务正文排成艺术字。

## 05. 真实界面组件规范

**导航**：深底，清晰图标与中英文层级；徽记一次展示；hover/active 显著但克制。手机底部固定三项，避免擅自新增业务入口。

**任务卡片/行**：无厚金属镶边；白纸/浅羊皮色面；标题永远是第一信息；完成按钮使用清晰状态，优先级通过低饱和标签和文本双重表达。逾期不能只靠红色识别。支持任务标题换行、长任务名、空列表、加载失败、键盘焦点。

**快捷添加**：可直接输入并保存。提示与按钮是 HTML，不烘焙到图像。错误保留草稿。移动端置于工作区可触位置。

**进度**：以已完成/今日到期口径显示；环形或线性均可，但数字与语义文字必须可读；不能因为装饰夸大统计。

**情境**：不要简单把骑士头像重复印在所有分类卡。可以从建筑/纹章资产取局部裁切纹理；颜色由情境个性决定但不破坏主题。

**AI 规划**：像“作战地图/规划手稿”的文字阅读体验，优先区分用户输入、AI 回复、建议任务、确认导入。AI 演示版必须明确不调用正式服务。

**任务详情/弹窗**：沿用真实 React 表单和可访问对话框；不要整张 parchment 图来模拟文本框。按钮聚焦、错误提示、滚动和键盘可用。

## 06. 素材生产方案：原件应如何拆分

| ID | 源资产（必须是独立文件） | Master 建议 | 网页交付 |
|---|---|---|---|
| A01 | 女骑士＋旗杆，透明底，含头发与完整铠甲 | 至少 2200×3300，最好 3000×4500 | `figure-desktop.avif`, `figure-mobile.avif`；必要时透明 WebP |
| A02 | 红白鸢尾花旗帜：至少一条横向延展和一条垂落 | 横幅 ≥4000px，透明背景 | `banner-flow.avif/webp`，独立可重新定位 |
| A03 | 建筑远景＋军阵，中世纪教堂与尖塔，高光左侧，右侧压暗 | ≥3840×2160 | `city-backdrop.avif` |
| A04 | 金色日轮：微颗粒旧箔质感，边缘不规则 | ≥1500×1500 或矢量几何＋独立金箔贴图 | `halo-gold.webp` + SVG 轮廓 |
| A05 | 羊皮纸表面：几乎不可见的纸纤维/暖色层次 | 1024×1024 无明显平铺接缝 | `paper-texture.webp`，低透明度 |
| A06 | 角色/旗帜在**手机端**重新排布的场景导出 | ≥1290×1800；不从桌面图暴力裁切 | `hero-mobile.avif` |
| A07 | Logo 鸢尾花、分隔符、状态小图标 | 矢量 | 统一 SVG 组件库 |

**制作质量说明**：单纯把原参考图 735px 通过插值扩成 4K，不能满足 A01/A02/A03 要求。需真实高分辨率重绘或逐资产生成并逐张审核。人物形象须一致：面部、头发、肩甲纹章、左手握杆、剑柄和旗帜形状不变。请检查手指、剑身透视、旗帜上的鸢尾花与教堂结构，避免生成细节破绽。

**网页性能说明**：以上是**源图 master**建议，不代表需要把多张原尺寸无压缩素材同时传给浏览器。针对 390/768/1440/1920 CSS px 生成变体，使用 `<picture>`/`srcSet`/`sizes`；AVIF/WebP；主视觉优先加载，远景/纹理可延迟；不用 CSS blur 假装艺术颗粒。

## 07. 美术审核门槛（不通过则不改线上）

1. **视觉叙事**：不看文字，3秒内能识别“执旗者 + 金轮 + 流动旗帜 + 教堂远景”。人物辨识优先于花纹数量。
2. **清晰度**：100% 查看脸、手、旗帜边界和盔甲高光没有明显马赛克、涂抹、重复纹理；DPR2 检查主体源像素足够。
3. **裁切**：桌面 1440×900、1920×1080；平板 768×1024；手机 390×844、375×812、320×720 均保留脸与手的构图重点。
4. **文本对比**：业务正文不叠在复杂画面上；正文/底色不低于 WCAG AA 正常文本 4.5:1；装饰性图案可低于此标准，但不能承载业务语义。
5. **功能**：增删改查、勾选、子任务、情境、AI 页与错误处理不退化；原有自动化测试需通过。
6. **真实截图**：以浏览器截图而不是概念生图审阅；必须覆盖桌面和手机，截图中浏览器实际读取 2x 原始图片资产。
7. **性能与响应式**：不横向溢出；无因图层遮盖导致的不可点击；主图 LCP 在典型移动网络下可接受。
8. **范围控制**：这次只做视觉，不凭视觉稿增加日历、天气、统计等尚未实现的功能。

## 08. 实施顺序：每一阶段有可检验产物

**阶段 0｜方向定稿**：此规范 + 原图构图审查 + 素材需求清单。输出：可以交给插画师/设计师/前端的唯一规范。

**阶段 1｜绘画资产制作**：单独 A01–A07，先签收人物清晰度与身份一致，再处理背景，不在这一步编造网站 UI。输出：源文件与透明原件、桌面/移动裁切稿。

**阶段 2｜无皮肤功能层**：桌面/手机建立布局栅格，所有用户操作仍是真实 HTML/React；使用占位纯色验证首屏和任务密度。输出：可点的纯布局预览。

**阶段 3｜分层装配**：按明确的层级将素材装配进网页；角色脸和手设置保护区，旗帜限制进入任务文字区。输出：真实网站视觉预览，而不是整张 UI 图。

**阶段 4｜视觉质检与回归**：100%图像细节、触控/键盘、空态/长标题/失败态/移动裁切、CI、GitHub Pages。通过后再更新正式版本。

## 09. 当前仓库审计与迁移说明（2026-10-26）

目前功能分支已包含：
- `client/public/art/hero-desktop.avif`、`hero-mobile.avif`：构图成品，仍**不等于已审核的独立原件 A01–A06**。
- `standard-bearer-foreground.webp`、`gothic-architecture.avif`：部分素材。
- `client/src/styles/global.css`、`heraldic.css`、`art-direction.css`、`editorial-home.css`、`final-art.css`：五层叠加样式，存在样式覆盖、后期维护风险。

**正式实施时**应整理为 `tokens.css`（令牌）、`layout.css`（布局）、`components.css`（交互组件）、`art.css`（绘画层），并删除/停止引入废弃的实验性规则。必须先用 GitHub Actions 验证，不直接替换正在使用的版本。
